# Standards and references

This file answers one question for every part of the repository: where does
it come from? Each row names the standard, regulation or vendor document the
implementation follows, the official reference implementation that confirms
the pattern, the file in this repository that applies it, and whether the two
agree. Links were opened and compared with the code on 4 October 2026.

Conventions: "matches" means the policy shape, statement names, condition
keys or parameter values in this repository are the ones the cited source
publishes. "follows" means the source describes the requirement and this
repository implements it in its own way. Deviations are listed in their own
section at the end.

## 4. Where this baseline deviates, and why

Each item is either a lab setting with the production value named, or an
accepted deviation that `evidence/poam-exceptions.csv` tracks.

| Item | Standard expectation | Baseline as published | Reason and production path |
|---|---|---|---|
| CloudTrail bucket Object Lock | AU-9, AU-11: audit records protected from deletion for the retention period (FedRAMP: at least one year retained, 90 days readily available) | `GOVERNANCE`, 1 day (`terraform.tfvars.example`) | Governance mode can be bypassed by the account administrator, which is what lets the lab be destroyed. Production: `object_lock_mode = "COMPLIANCE"` with retention matching the AU-11 narrative. |
| CloudFront minimum TLS | SC-8(1), NIST SP 800-52 Rev 2, Security Hub CloudFront.7 and .10: TLS 1.2 floor, custom certificate | Default `*.cloudfront.net` certificate, minimum TLSv1 | CloudFront does not allow raising the minimum on the default certificate. The code switches to `TLSv1.2_2021` as soon as `acm_certificate_arn` is set. Tracked as a POA&M exception. |
| Containment Lambda outside a VPC | Security Hub Lambda.3 | Not in a VPC | The function calls IAM, which has no VPC endpoint; placing it in a VPC would need a NAT gateway and add nothing to the control. Documented exception. |
| Config recorder role | Security Hub Config.1 prefers the service linked role | Customer role with `AWS_ConfigRole` | Both are documented by AWS; the customer role keeps the trust policy explicit and `aws:SourceAccount` scoped. No finding was raised. |
| Identity Center and SCP modules | AC-2, AC-6, SC-7 | Code only in the lab (`enable_identity_center`, `enable_organizations` false) | Identity Center and SCP administration belong to the organization's management account and are already delegated elsewhere in this organization. Validated with `terraform validate` and checkov; applied in a production organization from the management account. |
| NIST SP 800-171 revision | NIST withdrew Rev 2 on 14 May 2024 | Security Hub standard `nist-800-171/v/2.0.0` | 32 CFR 170 and CMMC Level 2 still assess against Rev 2, and Security Hub publishes only Rev 2. Re-evaluate when DoD moves to Rev 3. |
| Operating system and application cryptography | SC-13 validated modules end to end | Only the AWS side is covered (KMS, FIPS endpoints, service TLS) | Workload images and libraries must use validated modules themselves; `docs/fips-140.md` lists the options. |
