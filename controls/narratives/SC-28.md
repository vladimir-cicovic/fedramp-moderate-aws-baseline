# SC-28 Protection of Information at Rest

| Family | Baseline | Responsibility | Status |
|---|---|---|---|
| System and Communications Protection | Moderate | Shared (AWS performs encryption; customer mandates it and owns the keys) | Implemented |

Enhancements addressed: SC-28(1) cryptographic protection.

## Control summary

Protect the confidentiality and integrity of information at rest.

## FedRAMP Rev 5 parameters

- Cryptographic protection (SC-28(1)) for all information at rest using FIPS 140 validated modules; customer managed keys preferred so key policy and rotation are under the customer's control.

## Implementation

Every store that can be encrypted with a customer managed key is, and the
encryption is set at creation so it cannot be forgotten:

| Store | Encryption | Key |
|---|---|---|
| CloudTrail and Config S3 buckets | SSE-KMS with S3 Bucket Keys | logging |
| S3 access-logs bucket | SSE-S3 (the only option S3 log delivery supports) | AWS managed |
| CloudFront origin bucket (public static content) | SSE-S3 | AWS managed, by design |
| CloudWatch Logs: CloudTrail, flow logs, WAF, CloudFront, Aurora, Lambda | KMS | logging |
| EBS volumes and snapshots (account default) | KMS, enforced by `EbsEncryptionByDefault` | data |
| Aurora storage, automated backups, snapshots | KMS | data |
| Aurora Performance Insights | KMS | data |
| Secrets Manager (database master secret) | KMS | data |
| SNS alerts topic | KMS | alerts |
| SQS dead-letter queue | KMS | logging |
| Lambda environment variables | KMS | logging |
| Terraform state (lab: local; production: S3 backend with SSE-KMS) | KMS | logging |

**Integrity at rest.** S3 versioning on every bucket, Object Lock on the audit
bucket, CloudTrail digest validation, and Config's configuration history
provide tamper evidence.

**Account-wide defaults.** EBS encryption by default with the data key means
any instance or volume created by any means in this region is encrypted with
the CMK; the account-level S3 public access block prevents exposure of
encrypted or unencrypted objects alike.

**Detection.** Security Hub controls S3.17, EC2.7, RDS.3, RDS.27, SNS.1,
SQS.1 and the CloudWatch Logs KMS checks report any resource that drifts
from this standard; the conformance pack includes the corresponding Config
rules.

## Gaps and POA&M

- Two buckets use SSE-S3 for service or design reasons (access logs, public origin). Documented as accepted; the access-logs bucket contains request metadata only.
- Terraform state is local in the lab; move to an S3 backend with SSE-KMS and Object Lock before production.
